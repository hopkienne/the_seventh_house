# P01 — Đèn, hàng rào và chiếc chìa

**Chapter:** CH01. **Contract:** puzzle logic cụ thể để agent implement, không phải source đã có.

## Ý định và layout
Lantern x=2; real fence x=8; safe anchors x=6 và x=10; REAL key x=11; ERASED door x=15; photo x=18. X từ 0–24m, Z từ -1.5 đến 1.5m; Shared ground.

## State graph
Main controller dùng `LOCKED → AVAILABLE → IN_PROGRESS → SOLVED`. LOCKED chỉ dùng khi thiếu chapter-entry/essential condition; không dùng optional memory để khóa main. `WRONG_INPUT` trả feedback và giữ IN_PROGRESS, không state terminal. `CAPTURE/LOAD` phục hồi state đã commit. SOLVED là monotonic; interaction repeated không phát thưởng lại.

Action order khuyến nghị: `pickup_lantern` → `switch_at_anchor_a` → `cross_fence_erased` → `switch_real_anchor_b` → `collect_key` → `switch_erased_anchor_b` → `open_h01_door` → `inspect_photo`. Các bước inspect có thể được thực hiện lại; không buộc người chơi đi đúng thứ tự kiểm thử nếu dữ liệu đã hợp lệ.

## Đáp án bắt buộc
```json
{
  "key_id": "H01_DOOR_KEY",
  "door_phase": "ERASED"
}
```
Không đổi đáp án để code dễ hơn. Slot labels/cue VI/EN phải cho suy ra đúng đáp án này. Với P13/P14 đọc nhánh main/optional trong contract, không buộc thiếu memory phải dừng game.

## Inputs và outputs
Inputs: chapter ID, authoritative world phase, `action_id`, interacted `stable_id`, StoryState/Inventory/Journal readonly. Outputs: local state update, feedback key, optional once event và journal collect qua service; không trực tiếp ghi save hoặc sửa world mask.
`E01` được collect một lần theo interaction liên quan; `p01_solved=true` khi main puzzle đủ điều kiện.

## Persistence / reset
Snapshot: `state`, `completed_action_ids`, `slots` (dict), `inspected_ids` (set encoded array), `reward_committed` (bool). P13 thêm `optional_route_edges` và `route_validated`; P14 thêm `selected_ending`, `confirmation_committed` và `evacuation_groups_state`. Serialize IDs không Node references. Wrong input reset chỉ tentative slots khi cần, giữ clues đã collect. Reload mỗi intermediate state phải cho phép tiếp tục. `reset_local` trong debug không xóa progress của chapter khác; retail replay dùng checkpoint trước lựa chọn hoặc new slot.

## Hints theo cấp
| Cấp | Nội dung VI |
| --- | --- |
| 1 | Hàng rào không có bóng ở lớp kia. |
| 2 | Qua hàng rào rồi tìm chỗ nền còn ở cả hai phía. |
| 3 | Lấy chìa ở REAL, trở lại ERASED để mở cửa. |
Hints chỉ theo yêu cầu H/menu hoặc idle threshold cấu hình, không tự bật đáp án ngay. EN phải giữ nghĩa và placeholder. Hint dùng số/icon/text, không chỉ màu hoặc âm.

## Acceptance / test fixture
- **P01-HAPPY:** từ entry state hợp lệ, dùng actions trên implementation thật tới SOLVED; assert reward đúng một lần và exit mở.
- **P01-WRONG:** đổi một lựa chọn/slot, feedback quan sát được, không SOLVED nhầm và sửa lại được.
- **P01-LOAD:** serialize/restore sau từng action; solve tiếp; reward không duplicate và flags không bị reset.
- **P01-EXPLOIT:** Cửa chỉ mở với key; đi sâu Z không vòng hàng rào; switch cạnh vách không được teleport.
- **P01-ACCESS:** muted + reduced effects + large text + VI/EN, clue/feedback vẫn đọc được.

Evidence gồm unit/integration log, input replay và rendered capture đúng build. Không được đọc file đáp án rồi set solved bằng debug trong end-to-end test. Agent tạo runtime data ở `data/puzzles/P01.json`, adapter/controller trong `scripts/puzzles/` và fixture tại `tests/fixtures/puzzles/P01/`.
