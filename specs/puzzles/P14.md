# P14 — Cơ chế trả lại thời gian

**Chapter:** CH07. **Contract:** puzzle logic cụ thể để agent implement, không phải source đã có.

## Ý định và layout
Checkpoint trước xác nhận; A/B unlocked bởi main_p13_solved + reveal. C còn all memories + route_validated; ba nhóm evacuation authored, flood beat states không simulation.

## State graph
Main controller dùng `LOCKED → AVAILABLE → IN_PROGRESS → SOLVED`. LOCKED chỉ dùng khi thiếu chapter-entry/essential condition; không dùng optional memory để khóa main. `WRONG_INPUT` trả feedback và giữ IN_PROGRESS, không state terminal. `CAPTURE/LOAD` phục hồi state đã commit. SOLVED là monotonic; interaction repeated không phát thưởng lại.

Action order khuyến nghị: `inspect_debt_mechanism` → `unlock_choice_panel` → `choose_A_B_or_C` → `confirm_consequence` → `play_resolution` → `credits`. Các bước inspect có thể được thực hiện lại; không buộc người chơi đi đúng thứ tự kiểm thử nếu dữ liệu đã hợp lệ.

## Đáp án bắt buộc
```json
{
  "A": "REPLACE_ANCHOR",
  "B": "RETURN_TIME",
  "C": "VALIDATED_EVACUATION_THEN_RETURN"
}
```
Không đổi đáp án để code dễ hơn. Slot labels/cue VI/EN phải cho suy ra đúng đáp án này. Với P13/P14 đọc nhánh main/optional trong contract, không buộc thiếu memory phải dừng game.

## Inputs và outputs
Inputs: chapter ID, authoritative world phase, `action_id`, interacted `stable_id`, StoryState/Inventory/Journal readonly. Outputs: local state update, feedback key, optional once event và journal collect qua service; không trực tiếp ghi save hoặc sửa world mask.
`E14` được collect một lần theo interaction liên quan; `p14_solved=true` khi main puzzle đủ điều kiện.

## Persistence / reset
Snapshot: `state`, `completed_action_ids`, `slots` (dict), `inspected_ids` (set encoded array), `reward_committed` (bool). P13 thêm `optional_route_edges` và `route_validated`; P14 thêm `selected_ending`, `confirmation_committed` và `evacuation_groups_state`. Serialize IDs không Node references. Wrong input reset chỉ tentative slots khi cần, giữ clues đã collect. Reload mỗi intermediate state phải cho phép tiếp tục. `reset_local` trong debug không xóa progress của chapter khác; retail replay dùng checkpoint trước lựa chọn hoặc new slot.

## Acceptance / test fixture
- **P14-HAPPY:** từ entry state hợp lệ, dùng actions trên implementation thật tới SOLVED; assert reward đúng một lần và exit mở.
- **P14-WRONG:** đổi một lựa chọn/slot, feedback quan sát được, không SOLVED nhầm và sửa lại được.
- **P14-LOAD:** serialize/restore sau từng action; solve tiếp; reward không duplicate và flags không bị reset.
- **P14-EXPLOIT:** Cancel quay panel không mất checkpoint; fail route C retry, không forced B; final choice once, credits reachable.
- **P14-ACCESS:** muted + reduced effects + large text + VI/EN, clue/feedback vẫn đọc được.

Evidence gồm unit/integration log, input replay và rendered capture đúng build. Không được đọc file đáp án rồi set solved bằng debug trong end-to-end test. Agent tạo runtime data ở `data/puzzles/P14.json`, adapter/controller trong `scripts/puzzles/` và fixture tại `tests/fixtures/puzzles/P14/`.
