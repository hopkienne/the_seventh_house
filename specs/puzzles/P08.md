# P08 — Hồ sơ dưới vết bùn

**Chapter:** CH04. **Contract:** puzzle logic cụ thể để agent implement, không phải source đã có.

## Ý định và layout
Ba trang thể hiện trước/sau bằng giờ và hình phù hợp canon; tuần tra quanh tủ, cover định sẵn; checkpoint trước encounter.

## State graph
Main controller dùng `LOCKED → AVAILABLE → IN_PROGRESS → SOLVED`. LOCKED chỉ dùng khi thiếu chapter-entry/essential condition; không dùng optional memory để khóa main. `WRONG_INPUT` trả feedback và giữ IN_PROGRESS, không state terminal. `CAPTURE/LOAD` phục hồi state đã commit. SOLVED là monotonic; interaction repeated không phát thưởng lại.

Action order khuyến nghị: `collect_page_warning` → `collect_page_break` → `collect_page_flood` → `order_pages` → `open_archive`. Các bước inspect có thể được thực hiện lại; không buộc người chơi đi đúng thứ tự kiểm thử nếu dữ liệu đã hợp lệ.

## Đáp án bắt buộc
```json
{
  "sequence": [
    "WARNING",
    "DAM_BREAK",
    "VILLAGE_FLOOD"
  ]
}
```
Không đổi đáp án để code dễ hơn. Slot labels/cue VI/EN phải cho suy ra đúng đáp án này. Với P13/P14 đọc nhánh main/optional trong contract, không buộc thiếu memory phải dừng game.

## Inputs và outputs
Inputs: chapter ID, authoritative world phase, `action_id`, interacted `stable_id`, StoryState/Inventory/Journal readonly. Outputs: local state update, feedback key, optional once event và journal collect qua service; không trực tiếp ghi save hoặc sửa world mask.
`E08` được collect một lần theo interaction liên quan; `p08_solved=true` khi main puzzle đủ điều kiện.

## Persistence / reset
Snapshot: `state`, `completed_action_ids`, `slots` (dict), `inspected_ids` (set encoded array), `reward_committed` (bool). P13 thêm `optional_route_edges` và `route_validated`; P14 thêm `selected_ending`, `confirmation_committed` và `evacuation_groups_state`. Serialize IDs không Node references. Wrong input reset chỉ tentative slots khi cần, giữ clues đã collect. Reload mỗi intermediate state phải cho phép tiếp tục. `reset_local` trong debug không xóa progress của chapter khác; retail replay dùng checkpoint trước lựa chọn hoặc new slot.

## Hints theo cấp
| Cấp | Nội dung VI |
| --- | --- |
| 1 | Các trang kể cùng một đêm. |
| 2 | Dấu giờ giúp xếp điều đã xảy ra trước. |
| 3 | Cảnh báo, vỡ đập, rồi lũ tới làng. |
Hints chỉ theo yêu cầu H/menu hoặc idle threshold cấu hình, không tự bật đáp án ngay. EN phải giữ nghĩa và placeholder. Hint dùng số/icon/text, không chỉ màu hoặc âm.

## Acceptance / test fixture
- **P08-HAPPY:** từ entry state hợp lệ, dùng actions trên implementation thật tới SOLVED; assert reward đúng một lần và exit mở.
- **P08-WRONG:** đổi một lựa chọn/slot, feedback quan sát được, không SOLVED nhầm và sửa lại được.
- **P08-LOAD:** serialize/restore sau từng action; solve tiếp; reward không duplicate và flags không bị reset.
- **P08-EXPLOIT:** Capture giữ pages đã commit; không spawn enemy nhìn thẳng player sau load.
- **P08-ACCESS:** muted + reduced effects + large text + VI/EN, clue/feedback vẫn đọc được.

Evidence gồm unit/integration log, input replay và rendered capture đúng build. Không được đọc file đáp án rồi set solved bằng debug trong end-to-end test. Agent tạo runtime data ở `data/puzzles/P08.json`, adapter/controller trong `scripts/puzzles/` và fixture tại `tests/fixtures/puzzles/P08/`.
