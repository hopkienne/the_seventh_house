# P11 — Lối đi dưới ba hồi chuông

**Chapter:** CH06. **Contract:** puzzle logic cụ thể để agent implement, không phải source đã có.

## Ý định và layout
Ba cần gạt có 3 nấc; note ghi 1-3-2 bằng số/symbol, không rhythm timing; animation đối trọng trang trí.

## State graph
Main controller dùng `LOCKED → AVAILABLE → IN_PROGRESS → SOLVED`. LOCKED chỉ dùng khi thiếu chapter-entry/essential condition; không dùng optional memory để khóa main. `WRONG_INPUT` trả feedback và giữ IN_PROGRESS, không state terminal. `CAPTURE/LOAD` phục hồi state đã commit. SOLVED là monotonic; interaction repeated không phát thưởng lại.

Action order khuyến nghị: `inspect_counterweight_record` → `set_lever_one` → `set_lever_two` → `set_lever_three` → `confirm`. Các bước inspect có thể được thực hiện lại; không buộc người chơi đi đúng thứ tự kiểm thử nếu dữ liệu đã hợp lệ.

## Đáp án bắt buộc
```json
{
  "lever_values": [
    1,
    3,
    2
  ]
}
```
Không đổi đáp án để code dễ hơn. Slot labels/cue VI/EN phải cho suy ra đúng đáp án này. Với P13/P14 đọc nhánh main/optional trong contract, không buộc thiếu memory phải dừng game.

## Inputs và outputs
Inputs: chapter ID, authoritative world phase, `action_id`, interacted `stable_id`, StoryState/Inventory/Journal readonly. Outputs: local state update, feedback key, optional once event và journal collect qua service; không trực tiếp ghi save hoặc sửa world mask.
`E11` được collect một lần theo interaction liên quan; `p11_solved=true` khi main puzzle đủ điều kiện.

## Persistence / reset
Snapshot: `state`, `completed_action_ids`, `slots` (dict), `inspected_ids` (set encoded array), `reward_committed` (bool). P13 thêm `optional_route_edges` và `route_validated`; P14 thêm `selected_ending`, `confirmation_committed` và `evacuation_groups_state`. Serialize IDs không Node references. Wrong input reset chỉ tentative slots khi cần, giữ clues đã collect. Reload mỗi intermediate state phải cho phép tiếp tục. `reset_local` trong debug không xóa progress của chapter khác; retail replay dùng checkpoint trước lựa chọn hoặc new slot.

## Hints theo cấp
| Cấp | Nội dung VI |
| --- | --- |
| 1 | Ba dấu khắc không có cùng độ cao. |
| 2 | Bản ghi đặt chúng theo thứ tự của ba cần. |
| 3 | Chọn các nấc 1, 3, 2. |
Hints chỉ theo yêu cầu H/menu hoặc idle threshold cấu hình, không tự bật đáp án ngay. EN phải giữ nghĩa và placeholder. Hint dùng số/icon/text, không chỉ màu hoặc âm.

## Acceptance / test fixture
- **P11-HAPPY:** từ entry state hợp lệ, dùng actions trên implementation thật tới SOLVED; assert reward đúng một lần và exit mở.
- **P11-WRONG:** đổi một lựa chọn/slot, feedback quan sát được, không SOLVED nhầm và sửa lại được.
- **P11-LOAD:** serialize/restore sau từng action; solve tiếp; reward không duplicate và flags không bị reset.
- **P11-EXPLOIT:** Không dùng quá nhanh gây double trigger; mute audio vẫn suy ra đáp án; save giữ lever_values.
- **P11-ACCESS:** muted + reduced effects + large text + VI/EN, clue/feedback vẫn đọc được.

Evidence gồm unit/integration log, input replay và rendered capture đúng build. Không được đọc file đáp án rồi set solved bằng debug trong end-to-end test. Agent tạo runtime data ở `data/puzzles/P11.json`, adapter/controller trong `scripts/puzzles/` và fixture tại `tests/fixtures/puzzles/P11/`.
